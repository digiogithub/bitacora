Cancelled by owner decision (2026-10-07): Pando must only implement generic capabilities, never Bitacora-specific behaviour, and Bitacora ships semantic search with client-side solutions on the current API. I checked the code and the current API is enough:
- REST upsert (`handleUpsertKBDocument`) does not write mirror files, and `SyncDirectoryWithStats` only deletes documents that carry `source_path` metadata, so REST-only documents are safe.
- Hash skip, list, batch and delete-by-prefix are replaced by a machine-local sync ledger in Bitacora.
- Agent profiles, personas and the Bitacora MCP server go into the `.pando.toml` that Bitacora's managed mode generates (same pattern as git-in-track's `internal/pando/supervisor`), so no per-run MCP config is needed.

Cancelled children: BIT-US-0132, 0133, 0134 and BIT-T-0415..0422. The generic Rust SDK (BIT-EP-0018) is kept.
