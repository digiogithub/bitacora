# Client-side decorations spike (BIT-US-0119, BIT-T-0389)

Continues [[bitacora-v2-plan]]; findings in [[frameless-window]].

## What changed
- New `docs/design/frameless-window.md`: verified gpui-pre 0.3.8 / gpui-component 0.7.1 API usage, per-OS behaviour,
  fallbacks (Server, GNOME Wayland, macOS traffic lights, Windows hit-test) and the kit-vs-custom decision.
- `crates/bitacora-app/src/spike/csd.rs` (new; `frameless_options`, `describe`, `open`): throwaway proof window.
- `src/cli.rs`: `--spike-csd` flag; `src/app.rs`: routes to the spike and skips the single-instance lock.
- `src/ui/mod.rs`: `ui::frameless` facade (`TitleBar`, `window_border`, `Decorations`, `ResizeEdge`, `Tiling`,
  `WindowControls`, `WindowDecorations`).

## Why
Validate `WindowDecorations::Client` + transparent titlebar before restyling the shell (BIT-SP-0008.R4/R5).

## Verification
- `cargo test -p bitacora-app --lib csd`: 1 passed. `cargo clippy -p bitacora-app --all-targets --locked -- -D warnings` clean.
- `bitacora --spike-csd --smoke-test` on COSMIC Wayland and XWayland: `decorations: Client`, all controls supported.
- macOS, Windows, GNOME and compositor-less X11 not verifiable here (documented, in_review).
